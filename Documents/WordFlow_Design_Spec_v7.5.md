## 1. 项目概述与核心架构 (Overview & Architecture)

**WordFlow (字.迷)** 是一款基于 Web 技术构建的 3D 消除填字游戏。项目采用**运行时零网络请求（Zero-Network-at-Runtime）**架构：所有 3D 视觉、字符纹理、音效、词典与关卡数据均随应用一次交付，运行时不再发起任何 HTTP 请求，可部署为单文件静态网页。

### 1.1 核心技术选型

| 维度 | 选型 | 说明 |
|---|---|---|
| 宿主环境 | 单文件 HTML5 Web 应用 | 构建产物为单个 `index.html`，可部署于 CDN / Vercel / GitHub Pages / 本地双击 |
| 3D 引擎 | Three.js (WebGL) | 场景、立方体网格、相机、Raycaster 拾取；构建期内联，不走 CDN |
| 纹理生成 | Canvas 2D API | 离屏绘制字符与状态样式，生成 `CanvasTexture` |
| 音频引擎 | Web Audio API | 振荡器 + 包络合成全部音效与 BGM |
| 数据 | 内嵌 JSON / JS 模块 | AI 预生成关卡 + 词典，构建时打入单文件 |
| 构建 | Vite + `vite-plugin-singlefile` | 打包并内联为单 HTML |
| 存储 | localStorage | 进度 / 金币 / 设置 |

### 1.2 术语表 (Glossary)

| 术语 | 含义 |
|---|---|
| 方块 / Tile | 棋盘上一格，含 1 个字符，可为普通或障碍类型 |
| 棋盘 / Board | `grid_dim {x, y}` 定义的二维网格 |
| 目标词 / Target Word | 本关需要拼出并消除的词组 |
| 彩蛋词 / Bonus Word | 合法但非目标的词，存入额外词汇槽 |
| 路径 / Path | 玩家一次选取的相邻方块有序序列 |
| 步 / Move | 一次成功消除一个目标词（见 2.6） |
| 重力 / Gravity | 某列方块消除后，其上方方块沿列下落补位 |

## 2. 核心玩法规则详表 (Gameplay Rules)

> 本章为 v7.0 新增，用于消除 v6.0 的核心矛盾。**已确认采用模型 A：连线消除。**

### 2.1 棋盘与 3D 呈现

- 棋盘为**单层二维网格**，`grid_dim.x` 列、`grid_dim.y` 行，每格一个圆角骰子（`RoundedBoxGeometry`）。
- 逻辑坐标原点 `(0,0)` 位于左上；`x` 向右递增，`y` 向下递增。
- 渲染时：`worldX = (x - (cols-1)/2) * spacing`，`worldZ = (y - (rows-1)/2) * spacing`，`worldY = 0`。
- 相机为**固定透视相机，接近俯视**：仰角约 **67°**、`fov = 26` 并拉远，减小近大远小的透视畸变；**禁止旋转/缩放（已确认）**；相机距离按 `grid_dim` 与宽高比自适应。
- 方块之间留 `gap`，带轻微悬浮/自转/指针视差动画。

### 2.2 选取与提交

1. `pointerdown` 命中方块 → 成为路径起点，播放点击音，方块抬升/高亮。
2. `pointermove` 经过的方块：若与**路径末位**在 8 邻域内相邻，且未被本路径选中，则追加；否则忽略。
3. `pointerup` → 立即提交整个路径。
4. 备选操作：单击逐格累积（tap 模式），再次点击路径末位方块可撤销一格。
5. 路径约束：**8 方向相邻、不可跳格、不可重复（已确认）**。

### 2.3 字符序列与校验优先级

- 将路径方块字符按顺序拼接为字符串 `s`（可选包含其反转 `reverse(s)`）。
- 校验顺序：
  1. `s`（或反转）命中某个**未完成目标词** → 成功消除。
  2. `s`（或反转）命中 `bonus_dictionary` → 存入额外词汇槽。
  3. 否则 → 失败反馈（路径方块抖动 + 低沉音效），清除选中。
- ✅ 已确认：**允许反向匹配**。`reverse(s)` 与 `s` 等价参与校验（路径「水山」可命中「山水」）。

### 2.4 消除与重力

- 命中的目标词方块按障碍规则处理（见 3.2）。
- 消除产生空位后，**每一列**内其上方的方块整体下落，填补空位；列顶留空，**不生成新方块（已确认）**，棋盘总量单调递减，保证可通关。
- 下落为 Tween 平滑动画（默认 180ms，`easeOutCubic`），全部落位后检查级联（2.5）。

### 2.5 级联与连击 (Combo)

- **时间连击**：两次成功消除间隔 ≤ 3s，则 `combo += 1`；超过 3s 重置为 0。
- **级联消除（窄规则，已确认）**：重力落位后，**仅当某个原本“拼不出”的未完成词因掉落而“新凑成”**时，才自动消除该词，`combo += 1`（可链式）。
  - 判定“新凑成”= 消除前该词不可拼，消除后（重力落位）可拼。
  - **消除前就可拼的词不会触发级联**（避免把玩家本来就能选的词自动消掉）。
- 表现：每级 combo 播放递升和弦（音高随 combo 提升）并触发粒子爆炸；金币/得分倍率 = `1 + 0.2 * combo`。
- 关卡生成器会**刻意制造这种“新凑成”**：目标是让观察力强的玩家一步触发多词连锁（见 8.2）。

### 2.6 胜负与步数

- **通关**：所有目标词被消除。
- **失败**：炸弹爆炸（见 3.2）或 `move_limit` 步数耗尽。
- **一步的定义**：一次**成功消除目标词**的提交计 1 步（级联自动消除不额外计步）；失败提交不计步（已确认）。
- 当前所有关卡 `move_limit = null`（不限步），难度由障碍与链长提供。

### 2.7 HUD 布局

| 区域 | 内容 |
|---|---|
| 顶部 | 返回 / 向导、步数（`已用/上限` 或 `已用`）、金币 |
| 主目标槽 | 待找词列表（已找到置灰打勾，悬浮显示提示文案） |
| 额外词汇槽 | 彩蛋词收集格（默认 3 格）；**该关无彩蛋词时整行隐藏** |
| 中部 | 选中词预览（底部小药丸，空时淡出，不遮挡棋盘） |
| 底部 | 提示（普通/定向/魔棒）、重排、确定（选中 ≥2 时出现） |

### 2.8 死局与重排 (Deadlock & Shuffle)

- **死局判定**：剩余每个目标词在当前棋盘都无法拼出。
- **重排**：将剩余方块重新排布，保证所有未完成词再次可拼、且整关仍可解（内部用求解器校验）；保留字符与障碍状态。消耗 **30 金币**，**死局时免费**。
- **魔棒兜底**：魔棒在当前无词可拼时先自动重排再消除。
- 每次结算后若进入死局，提示玩家使用「重排」。

## 3. 零资源程序化实现 (Zero-Asset Directives)

### 3.1 3D 方块与文本纹理

- 严禁运行时加载 PNG/JPG/TTF/字体 JSON。
- **方块本体**：圆角骰子（`RoundedBoxGeometry`）使用**纯色材质**，按状态着色：普通米色 `#f0e4d6`、冰（hp>1 深/浅蓝）、锁（灰）、炸弹（淡红）；选中时以 `emissive` 发光并放大。
- **文字仅在顶面**：其余五面无任何文字。顶面贴一张 `PlaneGeometry` 透明贴片，纹理由离屏 `Canvas 2D`（256×256）绘制字符（带白色描边增强可读性）。
- 状态装饰（冰冻纹样、锁链交叉、炸弹倒计时数字）同样只画在**顶面贴片**上。
- 流程：
  1. 离屏 `Canvas 2D` 绘制顶面字符/装饰 → `new THREE.CanvasTexture(canvas)`。
  2. 贴片材质 `MeshBasicMaterial({ transparent: true, depthWrite: false })`，置于 `y = 顶面 + 0.005`，作为骰子的子节点。
  3. 状态变化通过**重绘顶面贴片**或修改本体材质颜色/自发光实现。
- 性能：顶面贴片按 `char + 状态` 缓存 `CanvasTexture`；方块共享同一几何体。

### 3.2 障碍方块规则

| 类型 | 字段 | 规则 | 备注 |
|---|---|---|---|
| 普通 | `type:"normal"` | 常规消除 | — |
| 冰冻 | `type:"ice", hp:2` | **路径级判定（已实现）**：若本次匹配路径中存在 `hp>1` 的冰方块，则整条路径仅“裂冰”（对所有冰方块 `hp-1`），**不消除任何方块**，保证可解；当路径内冰方块均 `hp≤1` 时正常消除 | 破冰不计额外步 |
| 锁链 | `type:"lock", lockKey:"w2"` | 未解锁时**不可被选中**。当 `lockKey` 指向的目标词被消除后自动解锁；`lockKey` 为空时相邻任一目标词消除即解锁 | 解锁永久 |
| 炸弹 | `type:"bomb", countdown:5` | 每成功消除 1 步 `countdown-1`；归零仍未消除 → 爆炸，**直接判负（已确认）** | — |

- 锁链/炸弹方块**不下落（已确认）**：锁定与炸弹方块固定在原格，其余方块下落。注：冰方块按普通方块处理，可随重力下落。

### 3.3 程序化音频合成

- 全局单例 `AudioContext`，**必须由首次用户手势创建/恢复**（浏览器 Autoplay 策略）。
- 音效合成：
  - 点击：`OscillatorNode` 正弦波 880Hz + 短衰减 `GainNode`（~80ms），模拟木鱼/水滴。
  - 消除：阶梯频率多振荡器，随 combo 递升和谐（默认 C 大调五声：C D E G A）。
  - 失败：低频锯齿波短促下坠。
  - 胜利：上行琶音。
- BGM：`setInterval`/`AudioBufferSourceNode` 循环播放五声调式低音量序列，默认音量 0.25。
- 设置项：`sfx`、`bgm`、`volume` 持久化（见 11.2）。

## 4. 游戏机制细节 (Mechanics)

### 4.1 双盘联动（主目标槽 + 额外词汇槽）

- **主目标槽**：本关全部目标词，命中后打勾置灰，推进通关。
- **额外词汇槽**：拼出 `bonus_dictionary` 中的词则填入彩蛋格，**不报错、不消除棋盘、不扣步**，并给予少量金币。集满 `bonus_target`（默认 3）格 → 奖励金币/提示道具并清空槽（数值见 10.1）。
- 彩蛋词由生成器**主动摆到棋盘上**保证可拼出（见 8.2）；该关无彩蛋词时 HUD 隐藏整行。

### 4.2 多级动态提示

| 提示 | 行为 | 成本 |
|---|---|---|
| 普通提示 | 按**已验证的标准解顺序**给出下一个可消除的词并预览其路径 | 20 金币 |
| 定向提示 | 玩家点选一格 → 预览包含该格的未完成词路径 | 40 金币 |
| 魔棒 | 自动完成一个未完成词；**当前无词可拼时先自动重排** | 80 金币 |

- 提示优先按标准解顺序，避免把玩家引入死局；死局时由「重排」或魔棒兜底（见 2.8）。

### 4.3 彩蛋生成 (Bonus Generation)

- 每关在 `tools/generate-levels.mjs` 中登记 1–3 个**真实词组**作为彩蛋候选。
- 生成器在摆完目标词后，将彩蛋词以直线路径摆入剩余空格（保证初始可拼），并剔除与目标词重复者；摆不下的逐个丢弃。
- 运行时只内嵌最终 `bonus_dictionary`，不做全量词典校验。
- 提示系统：首次进入含彩蛋的关卡时弹出「彩蛋词」情境提示（见 5.2）。

## 5. 玩家交互与射线拾取流程 (Interaction Flow)

1. 玩家在屏幕滑动或点击。
2. `Raycaster` 由相机与指针 NDC 坐标构建，与方块 `InstancedMesh`/`Mesh` 求交。
3. 高亮选中方块并播放点击音。
4. 按顺序连线字符，按 2.3 优先级校验。
5. 命中则播放消除动画与和弦、计算重力下落坐标并平滑补位；未命中则播放失败反馈并清空路径。

### 5.1 UX 屏幕流程

`启动(首屏点击解锁音频) → 主菜单 → 关卡选择 → 游戏 → 结算(胜/负) → 返回`

- 主菜单：开始、关卡选择、设置（语言/音效/BGM/音量）、重置进度。
- 结算页：得分、星级、金币、下一关/重玩。
- 暂停：继续、重开、返回、设置。
- 不提供逐步「撤销」（与重力/障碍状态机冲突且易被滥用）；仅提供「重开本关」并二次确认。选中路径在提交前可逐格撤销（见 2.2）。
- 「玩法向导」（完整 6 步图文）作为可选入口保留：首页「玩法向导」按钮、选关页 `?`、游戏内 `?`；**不再自动弹出**，改由情境提示承担新手引导。

### 5.2 情境向导 (Contextual Coach Tips)

- 以游戏内 coach mark 呈现：聚光高亮 + 说明卡片 + 「知道了」；同时只显示一条，逐条排队。
- 触发时机（每条**全局仅一次**，记录于存档 `flags.tips`）：
  1. **首次进入任意关卡**：`连线成词`
  2. **关卡含彩蛋词**：`彩蛋词`（高亮彩蛋槽）
  3. **关卡含冰/锁/炸弹**：对应障碍说明
  4. **首次消除后**：`重力下落`；**首次连击**：`连击`
  5. **首次进入**：`提示道具`（高亮底部按钮）
- 文案与插图均为程序化生成（SVG/Canvas），零外部资源，中英双语。

## 8. 关卡生成器算法 (Level Generator)

> v7.0 新增。生成器为**离线 Node 脚本**，产物内嵌进应用。运行时零请求。

### 8.1 工具

- `tools/generate-levels.mjs`（离线 Node 脚本，产物内嵌进应用，运行时零请求）。
- 输入：关卡规格 `SPECS`、彩蛋候选 `BONUS`、随机种子。
- 输出：`src/data/levels.js`（编译后的关卡对象数组）+ 控制台校验报告。
- 另有 `tools/verify-levels.mjs`（`npm run verify`）做回归。

### 8.2 生成流程

1. 按阶段选取 `grid_dim` 与目标词（见第 9 章）。
2. **链式嵌套摆放（核心）**：对每条链 `[w1..wk]`，递归构造单列序列——把前置词的字**插进后续词的字之间**。例如 `[A,B]` → 列（自顶向下）`B0 A0 A1 B1`：`A` 开局连续可拼，`B` 被 `A` 隔开不可拼；消除 `A` 后 `B` 落拢相邻 → 触发级联。链更长时递归套用（`[A,B,C]` → `C0 B0 A0 A1 B1 C1`），一步可连消多个词。
   - **词长混合**：链中可混用不同长度的词（中文 2/3/4 字，英文 3/4 字母），并随机决定插入点、整列翻转、垂直留白，使列高（4/5/6/8）与块型各不相同。
   - **每关种子由关卡 id 哈希生成**（而非固定/等长字段），确保各关随机序列独立、布局互不重复。
3. 将各链放入**不同列**（自列底向上），保证链长 ≤ 行数。
4. **其余目标词**以直线路径摆入剩余空格。
5. **彩蛋词**以直线路径摆入剩余空格，剔除与目标词重复者；摆不下的丢弃。
6. **填充剩余格**：填充字**排除目标词用字**，避免意外凑出延迟词而破坏链结构。
7. **障碍注入**：按配置随机升级若干格为冰/锁/炸弹。
8. **求解**：用第 8.3 的求解器生成 `solution_flow`（内部完整建模裂冰、解锁、重力、级联、炸弹倒计时）。
9. 记录链数、级联数，供报告与调优。

### 8.3 求解器与可解性断言

求解器 `solveBoard(cols, rows, tiles, words)`：按顺序尝试未完成词，模拟「裂冰 / 消除 / 解锁 / 重力 / 级联 / 炸弹」，回溯求一条可行解；失败状态用 `board.hash()+remaining` 记忆化剪枝。

生成器必须通过：

- **链首开局可拼、链上后续词开局不可拼**（否则重生成）。
- `solveBoard` 返回非空（存在可行解）。
- 不存在「目标词方块被永久移除」的死局（天然满足：无重叠生成，词只在完成时移除）。
- 乱序游玩 + 死局重排后仍可通关（见 8.4）。

### 8.4 随机可复现与回归

- 每关由固定 `seed` 生成，相同 seed 产出相同关卡。
- `npm run verify` 断言：全部关卡在「按标准解」与「乱序 + 重排」两种玩法下均可通关；彩蛋词均可拼出并计入彩蛋槽。

## 9. 难度曲线与数值配置 (Difficulty Progression)

> 已实现共 **24 关**（中文 12 + 英文 12）。曲线连续：先加词 → 引入级联 → 加长链与混合词长 → 加障碍。

| 阶段 | 关卡 | 棋盘 | 词数 | 链型 / 列高 | 最高效步数 | 机制 |
|---|---|---|---|---|---|---|
| 新手 | `zh/en_001–003` | 3×3 | 2 → 3 | 无链 | = 词数 | 纯找词 |
| 成长 | `zh_004–006` / `en_004–006` | 4×4, 4×5, 5×5, 6×6 | 3 → 5 | 1–2 条链（4–5 格） | 2–3 | 引入级联 |
| 进阶 | `zh_007–009` / `en_007–009` | 5×6, 6×6, 6×7, 7×7 | 4 → 6 | 1–2 条链（6–8 格，混合词长） | 2–5 | 长链 + 更多词 |
| 挑战 | `zh_010–012` / `en_010–012` | 6×6, 6×7, 6×8 | 4 → 5 | 长链（一步 3 词）+ 冰/锁/炸弹 | 2 | 全机制 |

- **词长混合**：中文 2/3/4 字（如春江水、山外山、春暖花开、山清水秀），英文 3/4 字母（如 CAT、TREE、MOON、LEAF），使链的列高与形状多样。
- 单关新增机制 ≤ 1 种，教学关保持简单（无级联、无步数限制）。
- 当前所有关卡 `move_limit = null`；难度由障碍与链长提供。
- 词数、棋盘、链长、障碍数量均为生成器参数，可继续调优。
